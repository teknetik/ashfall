# Day/night implementation handoff · 8 September 2026

Status: implementation and temporary compilation checks complete; saved-scene installation, fixture binding, Unity test execution and native visual/performance qualification remain with the integrating task. This is not a claim of AAA visual quality or a completed district lighting pass.

## What is implemented

- `DayNightLightingProfile`: ordinary editable serialized lighting keys and a configurable game clock. The default 40-minute cycle is a presentation setting, not new Tir orbital lore. Sorted keys interpolate continuously through midnight; all lighting values are validated. The installer samples the current authored sun rotation/intensity/color, sky fill, ambient colors, sky colors and volume exposure into the noon/default key instead of overriding them with assumed values.
- `CityTimeOfDay`: moves the key light through dawn/noon/dusk and a restrained blue night key; changes sky/cloud/fog colors, tricolor ambient, post exposure and lamp demand together. No geometry is constructed. Sky material and grading components are cloned at runtime, then restored and destroyed on teardown. The clock starts **paused at the authored default** for matched review. Change `startPaused` after qualification to run the ordinary cycle on launch.
- `WardDayNightSky`: a separate derivative of the existing original sky shader. It takes an explicit sun direction and visibility; the old unconditional yellow disc and halo cannot persist into night. The original sky shader/material are preserved. It uses the existing atmosphere wind time, so cloud motion follows reduced motion.
- `CityLightCircuit`: editable light/material references drive warm practical illumination and bulb emission together. Material identity is resolved once at runtime across active renderers, including rebuilt render chunks. Runtime material clones preserve the source assets. Local illumination fades between 28 and 42 metres; only lights already authored with shadows can cast them, with a smooth fade before 18 metres. All original light/material state is restored on disable.
- `CityTimeReflections`: keeps the existing global sky and dedicated courtyard probes, updating one probe at a time through Unity's individual-face time slicing. Global sky uses 128; local runtime resolution is capped at the existing resolution or 256 by the installer. Normal clock changes request updates after 0.3 game hours with at least eight real seconds between requests per probe. Accelerated review shortens this interval, bounded to one second and one capture in flight. A large hour/lighting jump suppresses stale cubemaps until the new capture is ready; updated reflections fade in over 0.35 seconds. The sky probe supplies the global fallback outside local probe boxes. Failed/rejected captures are recorded and cannot be mistaken for a current reflection.
- `DeveloperTimeMenu`: F8 opens a compact bronze UI Toolkit panel beside the undimmed scene. It offers dawn/noon/dusk/night presets, precise hour input, a slider, play/pause, 1×/10×/60× speed and reset. Gameplay is paused and movement/look/zoom/interaction are blocked. The clock alone can preview while the menu is open. Esc/F8 teardown restores the previous gameplay/pause state and input predicates. Menu code and time diagnostic cases are compiled only for Editor/DEBUG variants and additionally guarded by `Debug.isDebugBuild` in a player. Ordinary release compilation excludes command/UI code.
- Reduced motion limits accelerated clock playback to 1×, avoids an animated menu entrance and retains the existing frozen cloud/foliage wind behavior.

## Exact integration sequence

1. Finish the source mesh/fixture pass, rebuild render chunks where needed and save the actual `Assets/AthenHill/Scenes/AthenHill.unity` scene. Check the active Editor/instance and its console.
2. Run **Athen Hill → Day and night → Install clock and developer controls**, or `AthenHill.Editor.DayNightPass.Install()` through the working Unity MCP. It refuses Play Mode, an unsaved scene, duplicate clock/assets, missing required references or existing lightmaps requiring a separate sun/bounce audit. It saves a recoverable scene copy to `before-clock.unity`, creates ordinary profile/material assets under `Art/DayNight`, writes `installation.json`, and leaves the scene dirty for review/save. It never builds the player.
3. Select **Ward lighting clock → CityLightCircuit**. Add every intended practical lamp to `practicalLights` and its bulb material to `emissiveMaterials`. Author each light's full night intensity, range, color, and desired shadows; the circuit attenuates these for day/distance. Existing terminal screens/hums remain on their separate materials. The auto-binding only finds existing lamp-named local lights and `LampEmission` materials; it is not proof that fixture installation is complete. The current source scene has only Sun/Sky fill serialized directly; no local lamp lights were assumed to exist.
4. The `viewer` fields are bound to the actual world camera, so distance behavior is also correct in named review cameras. Check both serialized reflection bindings: global `City sky reflection` and local `Courtyard reflection`. Keep the global probe sky-only (`cullingMask=0`). No settings, graphics API, renderer or package version is changed.
5. Save, reopen and verify references/default lighting and the chunk source guard. Leave the clock initially paused for baseline comparisons. Run **Edit Mode → `AthenHill.Tests.DayNightTests`** (15 parameterized results expected), plus existing logic/movement checks.
6. Build the native Linux development player through the current project build workflow. Launch with an isolated QA preferences directory and `--athen-qa <evidence>/native`. Run:

   ```bash
   ATHEN_NATIVE_PID=<player-pid> ATHEN_NATIVE_DIR=<absolute-native-folder> \
     uv run --with python-xlib python unity/tools/check_day_night.py
   ```

   The test uses real F8/keyboard/pointer inputs, checks modal movement/jump/wheel blocking and pause restoration, checks reduced motion, captures matched dawn/noon/dusk/night at five existing cameras, records eight-second profiles per preset plus a 15-second accelerated transition profile, and verifies both reflection probes switch to current runtime captures. It **fails** when actual local lamp lights are absent, a reflection update fails, or controls leak. It leaves the development player open at the authored default for further route checks. It reports timing pass/fail without hiding failures or replacing the separate walking qualification. Override the comma-separated cameras with `ATHEN_TIME_VIEWS` if the current saved scene deliberately replaces a review view.
7. Give the native images and moving transitions to the separate visual critic. Review night route/character readability, bulb bloom/exposure, pools of light, sun/shadow direction, ground contact, canopy motion, reflection seams/popping and texture response. Correct the serialized profile/fixture settings, rerun affected native checks and preserve rejected captures. Build/release-test F8 and opt-in bridge absence, plus the current city verbs/real traversal.

## Remaining acceptance risks

No native dawn/night screenshot, actual Unity test execution, measured fixture shadow cost, reflection timing profile or release-input check has been produced by this agent yet. The profile is an initial art direction, not a calibrated final night. Dynamic reflection updates use installed APIs but still require the actual OpenGL shipping render to be verified. Their reported capture latency spans multiple frames and is **not GPU cost**. GPU/CPU frame counters are reported unavailable if nonpositive. These controls do not supply real-time diffuse GI; ambient is an art-directed sky/equator/ground approximation, with local direct fixture light. There are no baked-lightmap shadows in the expected scene, and the installer rejects them if present.
