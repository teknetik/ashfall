# Ward field pack — inventory grid and item inspection

Design handoff · 28 September 2026 · native Unity UI Toolkit only

## Basis and boundary

The current reference `image_03db16.png` shows a near-screen-width three-row list: two uncarried items receive equal visual weight to the single carried Scrap Coil, with large empty strips and descriptions consuming the panel. `image_35d9ae.png` suggests compact illustrated cells and a separate small equipment window; `image_ae0e4e.png` suggests quantity badges and a stable selection area. Borrow the information hierarchy, not their artwork, hex patterns, exact geometry, labels, game systems or statistics. The accepted Ward interface in `unity/DESIGN.md` governs chrome, typography and color. No new equip, crafting, drag/drop, weight, rarity, damage, health or durability systems are implied by the references.

This is a design specification, not an implemented or tested UI. The inspected working tree has partial uncommitted `GameSession`/`InventoryView`/`InventoryTests` changes, while the current `CityHUD.uxml`, `.uss` and `CityHud.cs` still display the old three-row pack. Preserve and reconcile that work; do not assume the partial implementation works. Do not alter the shop layout, its purchase/sale actions, the ten-slot hotbar (six actions and four empty reserves), game catalog IDs, serialized scene references, or gameplay routes for this pass.

## Layout at 1920 × 1080 reference resolution

Keep the shared dimmed shade and movable bronze frame, but give Inventory its own compact modal variant: about 740 × 620 reference px (maximum viewport width minus 32 px, maximum 88% of viewport height). A header reads `Field pack`, with a clearly labelled `Close · Tab / Esc` control; a short line `Supplies and salvage` sits below. Credits are a separate small readout, e.g. `25 credits`, not a fake item tile. Below, divide the scrolling content into a 4-column grid of about 76–84 px square cells on the left and a 230–260 px overview on the right; use 8–12 px gutters and preserve 20–24 px inner spacing. The overview remains stationary while the grid scrolls. If this shared modal architecture makes a fixed overview impractical, scroll the grid and overview together only after verifying keyboard focus stays visible. No three large inventory rows or phantom tiles for uncarried catalog entries.

Each carried item occupies one cell (not one cell per unit) with the existing original `UI/Art/flask.png`, `medkit.png`, `scrap.png` where the ID maps to one; art scales to fit within roughly 52–60 px without distortion. Put a legible high-contrast `×N` quantity badge at the lower right and an accessible name on the element/tooltip. Avoid image-only communication: the overview always prints the selected name and `N carried`. New item IDs without an icon get a neutral original Ward placeholder, never another item's misleading art. Use catalog order initially; keep slot positions stable for a given inventory snapshot, but refresh on a purchase, sale or reward. Do not present an artificial capacity or filled empty cells as real inventory slots. A tiny, noninteractive grid ground may aid alignment, but it must not imply capacity.

Initial selection is the first carried item and its overview; pointer hover temporarily previews another item and pointer exit returns to keyboard/last-click selection. Click selects without trading, consuming, equipping or closing. Arrow keys move among cells (left/right by one; up/down by column count, clamped to existing items); an offscreen focused cell scrolls into view. Keyboard focus uses the existing cyan perimeter in addition to a stronger inset/ivory name, while hover uses a subtle brighter charcoal. Do not rely on color alone. The overview shows the original icon, catalog name, actual `Shop.Quantity(id)`, and catalog description. Missing description gets `No description recorded.` rather than an invented attribute. Use text labels, not baked lettering in art. If quantity becomes zero, remove the tile immediately and select the nearest remaining item; if none remain, use the empty state.

Empty state: the grid area displays `Your field pack is empty.` and beneath it `Supplies you acquire will appear here.` The overview shows `No item selected.` with no quantity badge, stat table or disabled details window. Credits remain visible. This is an honest no-carried-items state, even if the catalog defines unowned items.

## Inspection subwindow

Shift+click on a carried tile opens a separate framed detail subwindow above the inventory, sized about 380 × 430 px at the 1080p reference size, clamped fully inside the viewport. Enter on the focused tile is the keyboard equivalent; Shift+Enter also works. The subwindow has an explicit `Close details · Esc` button and a larger existing item illustration. Show the catalog's name and full description, live `N carried`, and only actual recorded attributes. The inspected `ItemSpec` contains `id`, `name`, `description`, `buyPrice`, `sellPrice`, `startingQuantity`; `ShopModel` holds live quantity/credits. If showing prices, label them explicitly `Basic General list price · Buy N cr / Sell N cr` sourced from the item definition, never as value, durability or a transaction action. There is no need to expose internal ID or starting quantity as gameplay stats. Avoid an empty decorative stat grid. If the item is sold while the detail is open, close its subwindow and update the selection.

The detail frame is a child-layer interaction on top of Inventory, not a new city state or independent world action. Pointer input hits this top frame, background inventory cells do not activate while it is open, and world movement/look/interact remain blocked as for the parent modal. On opening, move focus to `Close details`; Esc closes only details and restores focus to its originating tile. Esc again closes Inventory and restores sensible Play focus. Tab from Inventory closes the whole pack, including details, in one press; from Play it opens the pack; it must not open the pack from startup, settings, dialogue, shop, pause or while a text field/popup needs Tab. Avoid the same key event closing and immediately reopening through UI focus traversal. Other modal keyboard behavior stays intact. The on-screen hint is context-specific (`Arrows · Choose   Enter / Shift+click · Inspect   Tab / Esc · Close`) rather than the current generic `Tab · Select` footer, and reverts in other modals.

## Styling, scale and accessibility

Use the existing nine-slice `frame.png` and `button.png`/`button-focus.png`, charcoal `#161e1e`, bronze `#a48a62`, ivory `#eee9dc`, muted `#bcbcad`, and focused cyan `#58d5d7`; captions must read over opaque charcoal, not over the 3D city. Bronze is structural, cyan identifies interaction, not a constant glow. Keep UI Toolkit text editable and images picking-ignored; tile buttons themselves handle click, pointer and focus. Original illustrations only. Maintain the accepted 18 px body / 30 px title scale at 1080p and at least the existing small-window 20 px label rule. No shimmering, auto-animated item borders, or hover-dependent-only facts; honor reduced motion.

At a small window (below 1500 px width or 900 px height), shrink to a viewport-clamped modal with 2–3 columns and stack overview below or above the grid, not a clipped side rail. Give the scroll region remaining height, keep close/credits/hint visible, ensure 44 px-or-larger target areas and 20 px text, and keep focused cells and the details close control on screen. A very short viewport may scroll the whole inventory content; detail subwindow should cap height and scroll its description instead of escaping the screen. Reposition/clamp movable windows on resize as the current HUD layout does. Check 1920 × 1080 plus at least one narrow and one short window in the native player.

Do not treat the current `InventoryView.Details` output as mandatory UI layout; it currently exposes internal item ID.
