# Ward native developer console + Item Lab (local only)

This is a separate Python-stdlib web tool for the native Linux Unity game. It does not run, build or modify the retired Vite/browser game. It does **not** start the Unity player.

## Start

From the repository root, in a terminal:

```sh
python unity/tools/devui/server.py --qa-dir "$HOME/ward-native-qa" --port 8765
```

Open `http://127.0.0.1:8765/`. The server binds **only** to 127.0.0.1. Run a verified **development** AthenHill player separately with `--athen-qa "$HOME/ward-native-qa"` (the exact same directory). A release build ignores that bridge. No game running means `NO DEV PLAYER`, not simulated stats. An old state becomes stale after 2 seconds; controls are disabled and the server rejects commands. Shut down the web server with Ctrl+C. If port 8765 is occupied, choose another `--port`. QA and draft paths must be under the current user's home and may not contain symlinks. The draft file is created at `unity/tools/devui/data/drafts.v1.json` by default; specify `--draft-dir "$HOME/ward-drafts"` to keep it elsewhere. Back up the draft JSON before bulk imports.

## Provenance and limits

The **NPCs** page lists the seven voiced characters by area, stable NPC ID,
voice, accent, ElevenLabs voice ID and installed dialogue-take count. Records
are served from the local SQLite database `data/npcs.sqlite3`, created from the
versioned `npc_roster.json` on server startup. The page is read only for now;
changing the roster alone cannot alter Unity's installed clips. The database
lives with the local draft data, while `npc_roster.json` reproduces it in new
worktrees and on other machines. This establishes the NPC section for later
authoring controls without changing gameplay IDs or routes.

The Session page is **Unity-authoritative**: `dev-state.json` schemaVersion 1 from an opt-in development player, refreshed every 0.5 seconds. It shows exposed state and the current `CityCatalog` item IDs, held quantities, authored tags/caps, crafting progression, fitted grip, loot event count and weapon recoil. The pistol acquisition flag remains exposed separately through `PlayerCombat.hasPistol`; the runtime catalogue and character loadout are authoritative for equipment. A grant can target only a live catalogue ID, respects its cap, and does not unlock a recipe merely by adding a servo through the dev bridge. The world-clock actions, bounded item/credit actions, two pre-authored encounter actions, range raise and scoped city-visit reset use Unity's `dev.*` bridge with correlated ACKs. There are no remote craft, fit, arbitrary prefab/position/spawn count or command-string actions: craft and fit at the native field fabricator. Encounter activation must still respect Unity tutorial order. Weather is unavailable: the game has no weather system. Full tutorial reset is not implemented. An ACK timeout is **unconfirmed**, not proof of failure. Do not run another `native_client.py` QA writer against the same command directory at the same time; the file bridge has a single command slot.

Item Lab records, tags, stats, recipe item/tag inputs and outputs, enemy loot, graph and diagnostics are **editable draft design data, not in-game changes**. ID matches are displayed alongside the read-only Unity Editor export snapshot at `/api/unity-crafting`, sourced from `unity/AthenHill/Assets/AthenHill/Data/Crafting/Export/ward-crafting.v1.json` (generated by `CraftingDataExporter.Export`). This export is a dated serialization of the actual `CityCatalog.asset` and `WardCrafting.asset`, not the current in-memory player state; rerun the exporter after modifying those assets. Matching IDs do **not** assert field parity. The draft seed differs from runtime in names/tags/caps, recipe timing/weapon gate/unlocks and enemy drop quantities/chances. The historical illustrative `weapon_scrap_pistol` draft ID is design-only; use the exported runtime item ID when creating an equipment draft. `cracked_ceramic_bearing` has no Unity item. Additional draft IDs without an export match are explicitly design-only. Draft save/import/export cannot mutate any Unity asset or active game session. Author changes deliberately in Unity serialized data, validate/export there, then rebuild the native player; do not feed the draft JSON to Unity as a migration. Graph “impossible” is a bounded draft reachability check based on positive draft loot probabilities, **not** a quantity-aware or probabilistic crafting guarantee. Orphans may intentionally be junk. Cycles are dependency checks, not proof of a game bug.

Drafts use an atomic fsync/replace JSON write, optimistic revision check, exact versioned schema, global unique stable IDs, input/item/tag references and numeric bounds. Import replaces saved drafts only after confirmation and server-side validation, including diagnostic computation and the 512 KiB serialized-on-disk limit. Graph diagnostics reject more than 20,000 expanded edges rather than risk unbounded output. Draft reads use no-follow regular-file opens and writes pin directory descriptors below home, rejecting symlink swaps; a hostile local process with the same user privileges can still race, replace, or modify these files and is outside the security boundary. Export downloads the current unsaved workspace. There is no write path to Unity assets. To revert, import a previously exported JSON with matching schema or restore a backup. Server-side POSTs require a per-process random CSRF header; Origin and Host are checked and CORS is not enabled. This protects against arbitrary webpages, **not** a hostile local process running as the same user. Do not expose the port via reverse proxy or LAN forwarding.

## OpenAI authoring and equipment design (2 October 2026)

The existing **Items** editor now includes descriptions, design notes, buy/sell prices, equipment associations and an OpenAI proposal panel. **Start from Unity catalogue** copies the current Editor export into a new draft or selects its existing draft ID without overwriting it. Refresh that export through `CraftingDataExporter.Export` after changing Unity data. The additive `character` export includes current body slots, equipment hosts, modifications and stat names. An older export still opens, with fallback slot labels.

**Equipment & augmentation** authors these draft roles:

- Implant hosts have exactly three augmentation sockets, with selectable body slots.
- Armour hosts have named plate, lining, motor and utility sockets.
- Augmentation and armour components declare compatible body slots and socket types.
- Effects have a stat ID, a flat bonus and a percentage bonus. The UI shows `8` for 8%; saved `CharacterModifier` data uses `0.08`.

These fields remain draft design data. Export JSON and review it alongside the Unity catalogue before applying accepted changes in the Editor. No automatic importer, balance change, stable-ID migration, prefab replacement or character voice assignment is performed. Existing saved schema-1 drafts remain valid; new fields are optional and bounded.

### Credential and model configuration

The server reads `OPENAI_API_KEY` from the process environment or the repository-root `.env`. In an isolated Git worktree it also finds the primary checkout's `.env` through Git's common-directory record. It never copies the secret. You can select a different existing local file with `--env-file /absolute/path/.env`. Env files are parsed as data, never sourced or executed; symlinks and oversized/non-regular files are refused.

The browser receives only key-presence status. The key is never placed in JavaScript, draft JSON, provenance, Unity Assets, builds or browser storage. Requests go from the local Python server to the fixed HTTPS OpenAI API origin, with TLS verification, redirects disabled, no automatic retries and one in-flight request at a time.

Default models, verified against official OpenAI documentation on 2 October 2026:

| Workflow | API | Default model | Server environment override |
|---|---|---|---|
| Item copy / ideas | Responses, `store: false` | `gpt-6-astra` | `ASHFALL_OPENAI_TEXT_MODEL` |
| Transparent item illustration | Images generations | `gpt-image-2.5-flare` | `ASHFALL_OPENAI_IMAGE_MODEL` |
| Character voice audition | Audio speech | `gpt-4o-mini-tts` | `ASHFALL_OPENAI_VOICE_MODEL` |

The server loads these model settings at launch. Model access, image organisation verification, API quota and billing belong to the associated OpenAI project. API usage is separate from Codex credits. The UI shows the actual configured models and actionable errors. It does not silently fall back to a different model or automatically retry a charged request.

### Review workflow

1. Select an item, describe its intended role/look and generate copy or an illustration. Text receives the brief, selected item fields and `lore.md`, with canon restrictions. Icon generation receives the item and visual brief. No source-code files are uploaded.
2. Review current and proposed copy side by side. The name starts unchecked; choose exactly which fields to apply. Apply changes only the unsaved local draft; **Save draft only** persists it. IDs, stats and references stay unchanged by AI copy.
3. Illustration generation retains the original transparent 1024×1024 PNG, with a 56-pixel preview for inventory readability. **Use in draft** attaches its local asset reference; **Download PNG** provides the source for deliberate Unity import.
4. **Creative desk** supports ideas/writing and built-in character voice auditions. Voice generation sends only the entered dialogue and performance direction. Listen to the WAV, download it for Unity, and keep AI-voice disclosure in the game's credits when shipping generated speech. Custom voice cloning is not part of this tool.
5. Every job has a downloadable generation record: exact brief, item snapshot, effective instructions, model, UTC dates, provider request ID, API usage when supplied, asset hash and result. Records and original media are stored in the ignored draft directory's `generated/` subfolder. Keep that folder with any exported draft that references its media. Nothing is automatically added to Unity.

**Cancel request** discards the result locally. A synchronous request already running at OpenAI may complete and incur a charge; another request remains blocked until that call finishes or times out. On server restart an unfinished job is labelled interrupted, never silently retried. The journal shows the 100 most recent records.

Official references: [Responses text generation](https://developers.openai.com/api/docs/guides/text), [structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [image generation](https://developers.openai.com/api/docs/guides/image-generation), [text to speech](https://developers.openai.com/api/docs/guides/text-to-speech).

`test_ai_authoring.py` adds credential-redaction/worktree discovery, review-only copy, restart history, cancellation, one-request concurrency, malformed/refused output, provider error redaction, image/voice provenance, traversal/symlink rejection and draft-schema checks. The browser authoring regression verifies that comparison text follows edits while preserving selected fields, selective proposal application, save persistence, three implant sockets, editable armour sockets, percent conversion, generated-image attachment, ideas, voice playback markup, history reload and narrow-screen overflow. Its images/audio are test fixtures, not evidence of live OpenAI image or voice quality.

The Unity export regression uses the actual exported catalogue with an isolated draft store. It copies a Mk.II implant, leg armour, cognition augmentation and assist motor through the browser, verifies supported fields and fractional effects against the export, saves and reloads them, and checks that copying an existing ID preserves local edits. Editing copied sockets or effects cannot alter the read-only export snapshot. It makes no provider calls and writes its report/screenshots under `unity/evidence/inventory-redesign-20261002/authoring-export`.

A separately approved **single live text request** succeeded on 2 October 2026 using `gpt-6-astra`: 2,257 input tokens, 94 output tokens, 2,351 total. The returned name/description/design-notes passed local validation. No proposal was applied to game data. Image and voice transport paths have mock coverage only; no live image/voice request was made for this change.
