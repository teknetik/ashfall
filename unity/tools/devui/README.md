# Ward native developer console + Item Lab (local only)

This is a separate Python-stdlib web tool for the native Linux Unity game. It does not run, build or modify the retired Vite/browser game. It does **not** start the Unity player.

## Start

From the repository root, in a terminal:

```sh
python unity/tools/devui/server.py --qa-dir "$HOME/ward-native-qa" --port 8765
```

Open `http://127.0.0.1:8765/`. The server binds **only** to 127.0.0.1. Run a verified **development** AthenHill player separately with `--athen-qa "$HOME/ward-native-qa"` (the exact same directory). A release build ignores that bridge. No game running means `NO DEV PLAYER`, not simulated stats. An old state becomes stale after 2 seconds; controls are disabled and the server rejects commands. Shut down the web server with Ctrl+C. If port 8765 is occupied, choose another `--port`. QA and draft paths must be under the current user's home and may not contain symlinks. The draft file is created at `unity/tools/devui/data/drafts.v1.json` by default; specify `--draft-dir "$HOME/ward-drafts"` to keep it elsewhere. Back up the draft JSON before bulk imports.

## Provenance and limits

The Session page is **Unity-authoritative**: `dev-state.json` schemaVersion 1 from an opt-in development player, refreshed every 0.5 seconds. It shows exposed state and the nine actual `CityCatalog` item IDs (the original three shop rows plus six crafting/loot items), held quantities, authored tags/caps, crafting progression, fitted grip, loot event count and weapon recoil. The pistol remains a separate `PlayerCombat.hasPistol` state, not a catalogue item. A grant can target only a live catalogue ID, respects its cap, and does not unlock a recipe merely by adding a servo through the dev bridge. The world-clock actions, bounded item/credit actions, two pre-authored encounter actions, range raise and scoped city-visit reset use Unity's `dev.*` bridge with correlated ACKs. There are no remote craft, fit, arbitrary prefab/position/spawn count or command-string actions: craft and fit at the native field fabricator. Encounter activation must still respect Unity tutorial order. Weather is unavailable: the game has no weather system. Full tutorial reset is not implemented. An ACK timeout is **unconfirmed**, not proof of failure. Do not run another `native_client.py` QA writer against the same command directory at the same time; the file bridge has a single command slot.

Item Lab records, tags, stats, recipe item/tag inputs and outputs, enemy loot, graph and diagnostics are **editable draft design data, not in-game changes**. ID matches are displayed alongside the read-only Unity Editor export snapshot at `/api/unity-crafting`, sourced from `unity/AthenHill/Assets/AthenHill/Data/Crafting/Export/ward-crafting.v1.json` (generated by `CraftingDataExporter.Export`). This export is a dated serialization of the actual `CityCatalog.asset` and `WardCrafting.asset`, not the current in-memory player state; rerun the exporter after modifying those assets. Matching IDs do **not** assert field parity. The draft seed differs from runtime in names/tags/caps, recipe timing/weapon gate/unlocks and enemy drop quantities/chances. The illustrative `weapon_scrap_pistol` item is design-only: Unity models that weapon in `CraftingCatalog.weapons` and `PlayerCombat.hasPistol`, not `CityCatalog.items`. `cracked_ceramic_bearing` has no Unity item. Additional draft IDs without an export match are explicitly design-only. Draft save/import/export cannot mutate any Unity asset or active game session. Author changes deliberately in Unity serialized data, validate/export there, then rebuild the native player; do not feed the draft JSON to Unity as a migration. Graph “impossible” is a bounded draft reachability check based on positive draft loot probabilities, **not** a quantity-aware or probabilistic crafting guarantee. Orphans may intentionally be junk. Cycles are dependency checks, not proof of a game bug.

Drafts use an atomic fsync/replace JSON write, optimistic revision check, exact versioned schema, global unique stable IDs, input/item/tag references and numeric bounds. Import replaces saved drafts only after confirmation and server-side validation, including diagnostic computation and the 512 KiB serialized-on-disk limit. Graph diagnostics reject more than 20,000 expanded edges rather than risk unbounded output. Draft reads use no-follow regular-file opens and writes pin directory descriptors below home, rejecting symlink swaps; a hostile local process with the same user privileges can still race, replace, or modify these files and is outside the security boundary. Export downloads the current unsaved workspace. There is no write path to Unity assets. To revert, import a previously exported JSON with matching schema or restore a backup. Server-side POSTs require a per-process random CSRF header; Origin and Host are checked and CORS is not enabled. This protects against arbitrary webpages, **not** a hostile local process running as the same user. Do not expose the port via reverse proxy or LAN forwarding.

## Checks

```sh
python -m unittest discover -s unity/tools/devui -p 'test_*.py' -v
node --check unity/tools/devui/app.js
```

Tests cover no-player refusal, Host/Origin/CSRF and request-size checks, invalid commands, read-only Unity Editor export mapping, schema validation, graph diagnostics including a 999-edge chain, draft save/import conflict, oversized pretty serialization with restart readback, and draft-file/directory symlink swaps. A fresh integrated native development build and real player-to-UI readback, release-build bridge denial and full traversal require independent final QA. Do not substitute synthetic `dev-state.json` for live evidence.
