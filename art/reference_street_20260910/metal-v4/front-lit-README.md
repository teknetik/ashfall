# Door-front standard Lit route — 10 September 2026

This is the preferred staged route for the four door wear layers. It replaces the earlier proposed projector/custom-shader integration, while preserving those raw layer maps as source. Raw opacity layers still must not be bound directly as tiled Lit textures.

The twelve exact coated receiver meshes each contain two planar outward front triangles. All four front vertices are shared with the bevels. Duplicate those four vertices in a derivative mesh, move the same two triangles into submesh1, and give only those duplicates planar UV0 with +U=+worldZ and +V=+worldY. Retain every original vertex-buffer byte and all186 nonfront triangles per mesh in submesh0. Recompute only the duplicates' tangent/handedness for the new basis. Their positions, normals and every other attribute remain byte-identical to their originals. This changes1792 vertices to1840 and preserves2256 triangles and their winding. No surface is overlaid, moved, extruded or added.

`front-lit-contract.json` records the exact mesh/meta hashes, source material path/GUID/hash, saved prefab renderer IDs and the actual saved scene material overrides. All12 bind the existing FieldCoatedSteel v3 or FineryDoorCoatedSteel v3 material; bronze, kickplates, seals, frames, stone and factory brush meshes are excluded. Whole-source world positions/normals and exact front triangle IDs/slab planes are checked again in the real Editor before installation. The saved whole-scene SHA is historical context, not a lock against root's unrelated canopy work.

The route has four unique front materials. It retains each part's original material on bevels, sides and backs. The world-registered quiet coating and wear align across stacked leaf/insets, but the older nonfront texture phase remains on the small bevels: inspect those junctions and boundary roughness. Unique maps add texture residency and material buckets; no draw-count or performance claim is made before the native run. Exact layer dimensions are retained, with NPOT resizing disabled and importer max set to the next power of two that admits the actual source. No source maps are downsampled.

Source compositing can run in the existing Blender session **before live Unity inspection**. It is a reversible image operation defined by the authored door layer ranges and saved front coordinate contract. The compositor checks that its contract door ranges, handle/hinge registration, quiet-coat4m tile and output pixel dimensions exactly match the source recipe. It does not read live Unity state or require an inspection report. If the current door or hardware later differs, live inspection must reject installation of these maps until the registration is corrected; that does not require an extra Unity launch before making a source audition.

The staged entry points are:

1. The exclusive live Blender operator runs `author_metal_v4.py` AUTHOR. The candidate-v1 manifest now confirms all six source families were authored and all six color/precision readback guards passed. Source preview and visual review are separate from that technical success.
2. In the same live authoring session run `compose_door_front_lit_v1.py` with `COMPOSE_SOURCE_REVISION='candidate-v1'`, `COMPOSE_REVISION='candidate-v1-litfront-v1'`, `RUN_DOOR_FRONT_COMPOSITE=True`. It verifies the successful source manifest and exact16-bit PNG CRC/hash/schema, then writes a new folder without changing any Blender scene or mesh. Quiet coat is sampled at its4m tile in worldZ/Y and coverage-blended once with the unpremultiplied door layer. Normals share +Z/+Y/−X, so complete-material vectors are blended and normalized without a red flip. BaseColor is explicit sRGB; Normal and packed MetalSmooth are linear. Packing is R=metallic, G/B=0, A=1−roughness. Numeric PNG decode avoids Image.pixels/OCIO ambiguity for these authored intermediates.
3. Review the composed source result and finish/save/close Blender before reopening Unity on this memory-limited host. Root loads the staged Editor helper and calls `AthenHill.Editor.DoorFrontLitPass.Inspect("preflight-v1")`. Live inspection is mandatory before installation, but is not a prerequisite for steps1–2. It checks exact source mesh/material/world-geometry, actual handle bounds, hinge positions and front eligibility, and exercises the raw-buffer split in memory. It creates no art Assets or scene assignments. Evidence uses a fresh folder. Read-only Inspect records a stale chunk fingerprint instead of failing because unrelated canopy sources changed; it still requires a clean saved scene and the existing source roster outside ShowSources editing mode.
4. Rebuild any currently stale chunks, then root invokes `DoorFrontLitPass.Apply("candidate-v1-litfront-v1")`. Apply repeats the live target and hardware checks, requires a current source/chunk state, and copies three derivative maps per leaf. It clones standard URP Lit materials, validates public BaseShaderGUI/LitGUI keywords, and installs derivative meshes only on the12 allowed receivers. Original meshes/materials and nonfront data stay intact. It snapshots the current unchanged serialized components and roots, including colliders, nine actors and four routes, then explicitly rebuilds chunks and checks preservation. This snapshot is taken at Apply time; it does not compare canopy materials with a historical scene. Before-scene backups and failure evidence are retained.
5. Root verifies the saved/reopened scene and shipping native build: matched door close-ups at noon and completedhour16 reflections, moving approach/threshold views, and existing real-input gameplay/qualification. Check borders, wear registration, normal orientation and fine scratch stability. Source preparation does not establish native acceptance.

There is no historical whole-scene SHA or unrelated canopy-material hash lock in the helper. Apply's global fingerprint gate checks that the current saved source roster and disposable chunks agree before another edit/rebuild; it is not a source-compositing dependency. Final preservation compares unchanged components against their state at the beginning of Apply. Exact hashes are enforced only on the12 target meshes, their two old coated materials, source inputs and this front contract.

`front-lit-offline-validation.json` retains the first source-buffer/winding simulation,16-bit codec round trips and compilation evidence. `front-lit-staging-review-v2.json` records this revised orchestration and current helper/compositor checks. Actual Unity MeshData execution, composed front-map review and native acceptance remain pending. The compositor continues to refuse source maps whose readback guard failed.
